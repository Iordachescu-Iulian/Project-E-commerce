# Hexora P2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the P2 milestone for Hexora: a working Next.js + MySQL prototype with catalog, search and accounts, plus the frozen specification, ERD, architecture, API list, payment sequence, wireframes, P2 deck and PDF, and a three-branch GitHub workflow.

**Architecture:** Next.js 14 App Router with Server Components for shop pages and route handlers for the API. Prisma talks to a project-local MySQL 8.0.36 instance on port 3307. Auth is custom bcrypt + signed httpOnly JWT cookie. Stripe test mode is wired through a signature-verified webhook and an idempotent payment-event service. The work is split into a shared foundation on `main` and three feature branches, one per member.

**Tech Stack:** Node 18.17, Next.js 14.2, React 18, TypeScript, Tailwind CSS 3.4, Prisma 5.22, MySQL 8.0.36, bcryptjs, jose, zod, Stripe SDK, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-12-hexora-p2-design.md`

## Global Constraints

- Stack must stay Next.js + React + Tailwind + Node.js + MySQL + Stripe test mode, as presented in P1.
- MySQL is the project-local instance on `127.0.0.1:3307`; never touch the existing service on 3306.
- Startup must take at most five commands; secrets live only in `.env`, and `.env.example` is the only env file committed.
- Catalog pagination is at most 24 products per page.
- Seed data: 4 categories, 16 games, 32 purchasable editions (digital + physical), each with image, price and stock.
- All customer-facing pages must be usable at 360 px width.
- The P2 deck is at most 15 slides; the specification PDF is at most 8 A4 pages.
- Bonus scope is only B4 (sales dashboard) and B5 (discount codes).
- Access control is enforced on the server; hidden UI is not enough.
- Every member commits their own branch; commits use each member's GitHub-linked email.
- AI use must be declared in the README.

## Review Focus

- **Pagination and search edge cases:** page 0, page beyond the last page, pageSize above 24, empty query, no results, and special characters must not crash or return the wrong page size.
- **Auth boundary cases:** duplicate email, wrong password, missing/tampered/expired session, a customer editing another customer's address, and a customer calling an admin-only route.
- **Webhook correctness:** invalid signature must return 400; duplicate event id must be stored once; an unknown order id must not crash; a paid event for an out-of-stock order must roll back and leave the order unpaid.
- **Stock integrity:** two paid events for the last unit must not both succeed; cancellation must restore stock exactly once.
- **Responsive and missing-image behavior:** every customer page at 360 px, and a product with a missing image must show a fallback rather than a broken layout.

### Task 5: Stripe webhook and security groundwork (Rares)

**Files:**
- Create: `src/lib/stripe.ts`, `src/server/services/payments.ts`, `src/app/api/webhooks/stripe/route.ts`
- Modify: `src/lib/security.ts`, `next.config.mjs`
- Create: `docs/payments.md`, `scripts/test-webhook.mjs`
- Test: `src/lib/stripe-signature.test.ts`, `src/server/services/payments.test.ts`

**Interfaces:**
- Produces: `stripe`, `isStripeConfigured`, `recordPaymentEvent(event)` → `{ received: true, duplicate: boolean }`, `markOrderPaid(orderId, paymentIntentId)`, `restoreStockForCancelledOrder(orderId)`, `assertSameOrigin(req)`, `jsonError(status, message)`.

- [ ] **Step 1: Write the failing signature and idempotency tests**

Use `stripe.webhooks.generateTestHeaderString` to sign a payload with `whsec_test_secret`; `constructEvent` accepts it and rejects a modified payload/signature. Idempotency: a fake Prisma client returns an existing `PaymentEvent` for the same `stripeEventId`, so `recordPaymentEvent` returns `{ duplicate: true }` and does not create. Run `npm test`; expect failures.

- [ ] **Step 2: Implement the Stripe client and webhook route**

Route reads the raw body with `await req.text()`, requires `stripe-signature`, calls `constructEvent`, returns 400 on failure, calls `recordPaymentEvent`, returns 200. Set `export const runtime = 'nodejs'`. Use `STRIPE_WEBHOOK_SECRET` from `.env`; if missing, return 503 with a clear error, not a crash.

- [ ] **Step 3: Implement the payment-event service**

`recordPaymentEvent` upserts by `stripeEventId`; duplicate returns `{ duplicate: true }`. For `payment_intent.succeeded` with `metadata.orderId`, call `markOrderPaid` in a transaction: if the order is already `PAID`, no-op; otherwise update to `PAID`, set `paidAt`, append `OrderStatusHistory`, and conditionally decrement stock for each item (`stock >= quantity`). If any decrement affects zero rows, throw and roll back. For `payment_intent.payment_failed`, record the event only; the order stays `UNPAID`. `restoreStockForCancelledOrder` increments stock exactly once when an order moves to `CANCELLED`.

- [ ] **Step 4: Add security headers and same-origin checks**

`next.config.mjs` sets `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`. `assertSameOrigin` rejects mutating requests whose `Origin` does not match the request host; call it from auth/address mutating routes.

- [ ] **Step 5: Add the Stripe docs and test script**

`docs/payments.md` documents the test cards (`4242 4242 4242 4242`, decline card), `stripe listen --forward-to localhost:3000/api/webhooks/stripe`, `stripe trigger payment_intent.succeeded`, and the env variables. `scripts/test-webhook.mjs` sends a signed test event to the running app twice and prints the duplicate result.

- [ ] **Step 6: Verify the webhook live**

Send a request with `stripe-signature: t=1,v1=bad`; expect 400. Run `scripts/test-webhook.mjs`; expect first `{ duplicate: false }`, second `{ duplicate: true }`. Confirm no order is marked paid when the order id is unknown.
